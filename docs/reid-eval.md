# Оценка ReID: протокол, метрики и ограничения

Документ описывает `apps/reid_eval` и `apps/reid_bench` — инструменты измерения
качества и стоимости поиска в модуле `trafficmcmt_reid`. Он обязателен к
обновлению при изменении протокола оценки, метрик или формата manifest.

## 1. Что измеряется

| Инструмент | Вопрос | Выход |
|---|---|---|
| `trafficmcmt_reid_eval` | насколько хорошо дескриптор возвращает «свои» треклеты | CMC Rank-1/5/10, mAP@R |
| `trafficmcmt_reid_bench` | сколько стоит один поиск и какова цена приближения | p50/p95/p99, QPS, recall@k |

Оба приложения — часть Этапа 3 и не линкуют OpenCV/MTT. `reid_eval` требует
`trafficmcmt_io` (protobuf) для чтения треклетов; `reid_bench` собирается всегда.

## 2. Два режима `reid_eval`

### 2.1. Chunk-split наших треклетов (`--tracklets`)

Идентичность треклета — `(session_id, camera, local_track_id)`. Внутри одной
идентичности чанки упорядочиваются по `sequence` (при равенстве — по `id`) и
делятся по чётности:

```
sequence % 2 == 0  ->  gallery
sequence % 2 == 1  ->  query
```

Соседние по времени чанки попадают в разные половины, поэтому запрос не может
тривиально совпасть сам с собой. Это проверка **согласованности дескриптора
внутри трека**, а не кросс-камерный ReID: камера в идентичности фиксирована.

В этом режиме `exclude_same_camera` принудительно выключается — иначе чанки
одной камеры не смогли бы найти друг друга. Self-match исключается по `id`.

### 2.2. Внешний размеченный сплит (`--manifest`)

Манифест — JSONL, по одному объекту на строку:

```json
{"id":1,"identity":"track-7","camera":"cam-1","model_id":1,"split":"gallery","embedding":[0.1,0.2,0.3]}
```

| Поле | Обязательно | Тип | Смысл |
|---|---|---|---|
| `id` | да | number | уникальный `TrackletId` |
| `identity` | да | string | эталонная идентичность (объект) |
| `camera` | нет | string | камера; пустая допустима, в галерее заменяется на `unknown` |
| `model_id` | нет | number | id ReID-модели; по умолчанию 0 |
| `split` | да | string | `"gallery"` или `"query"` |
| `embedding` | да | array of numbers | вектор; размерность должна совпадать во всём файле |

Парсер — минимальный, собственный (без внешних JSON-зависимостей): плоские
объекты, строки с escape-последовательностями, числа, массивы. UTF-8 BOM в
начале файла допускается. Пустые строки игнорируются.

Именно этот режим нужен для кросс-камерного Rank-1: `identity` задаётся
вручную и не привязана к камере.

## 3. Метрики

Обозначения: `R` — число галерейных записей той же идентичности, что и запрос;
`rel(i)` — индикатор «i-й результат релевантен»; `rank` — позиция первого
релевантного результата (1-based).

**CMC (Cumulative Matching Characteristics).** Запрос считается успешным на
глубине `k`, если первый релевантный результат попал в top-k:

```
CMC(k) = |{q : rank(q) <= k}| / |Q_evaluated|
```

`reid_eval` печатает Rank-1, Rank-5 и Rank-10; `--max-rank` расширяет таблицу
(минимум 10).

**mAP@R (mean Average Precision).** Для запроса:

```
AP = (1 / R) * Σ_{i=1..|hits|} rel(i) * (Σ_{j=1..i} rel(j)) / i
```

Суммирование прекращается, когда найдены все `R` релевантных записей. mAP —
среднее `AP` по оценённым запросам.

**Глубина поиска.** `top_k = max(1, min(|gallery|, max(max_rank, max R)))`, чтобы
mAP видел все релевантные записи, а не только top-10.

**Пропуски.** Запрос без единой галерейной записи своей идентичности не может
быть оценён: он попадает в `skipped` и не входит в знаменатель. Если оценённых
запросов нет, приложение завершается с ошибкой данных.

**Фильтры.** В manifest-режиме учитываются `model_id` запроса и
`--min-similarity`; self-match исключается по `id`. Кандидаты с другим
`model_id` не сравниваются.

## 4. `reid_bench`

Генерирует детерминированные L2-нормированные векторы (`--seed`), строит индекс
через `Rebuild` и измеряет каждый запрос `std::chrono::steady_clock`:

- `build_ms` — время построения/обучения индекса;
- p50/p95/p99/max — перцентили латентности одного `Search`;
- `qps` — число запросов / суммарное время;
- `recall@k` — доля найденных соседей относительно точного inner-product скана
  (считается для приближённых индексов, на первых ≤ 50 запросах).

Google Benchmark не используется: нужны перцентили и recall, а не только
среднее, и не хочется тянуть зависимость в CPU-only CI.

## 5. Локальные результаты

Windows, MSVC 19.51 (VS 2026), Release, 8 потоков. Дата — 2026-11-08.

| Набор | Режим | Gallery | Queries | Identities | Rank-1 | Rank-5 | Rank-10 | mAP |
|---|---|---|---|---|---|---|---|---|
| Aire (1 камера) | chunk-split | 87 | 78 | 33 | 0.4615 | 0.7949 | 0.8718 | 0.3439 |
| Auburn (2 камеры) | chunk-split | 117 | 109 | 32 | 0.7523 | 0.9817 | 1.0000 | 0.6078 |

| Индекс | Векторы × dim | Запросы | p50 | p95 | p99 | max | QPS | recall@10 |
|---|---|---|---|---|---|---|---|---|
| `brute` | 200 000 × 512 | 200 | 12.6 мс | 14.9 мс | 16.2 мс | 16.8 мс | 77.8 | 1.0 |

Разброс между прогонами на одной машине — до ~20% (фоновая нагрузка, частота CPU),
поэтому числа стоит читать как порядок величины, а не как эталон.

Manifest-режим проверен smoke-тестом на 5 записях: Rank-1 1.0, mAP 1.0.

## 6. Ограничения

- **Chunk-split ≠ кросс-камерный ReID.** Значения 0.46/0.75 характеризуют
  стабильность дескриптора вдоль трека. Целевой Rank-1 ≥ 0.85 из DoD требует
  размеченного сплита (`--manifest`).
- **FAISS не проверен.** На машине разработки пакет не установлен, поэтому
  `FaissIndex` и `test_faiss_index.cpp` не компилировались. Все числа выше
  получены на `BruteForceIndex`.
- **Brute force memory-bound.** Один запрос читает `N·dim·4` байт: 410 МБ при
  200k×512. p99 < 20 мс на 1M×512 точным сканом недостижим — нужен
  `faiss_ivf_pq`. `reid_bench` держит данные и копию в индексе (~4+ ГБ RAM на
  1M×512).
- **Нет обучения нормализатора.** `EmbeddingNormalizer` принимает готовый
  артефакт `TMCMTWN1` (mean + матрица); тренер whitening/PCA вне этапа.
- **Идентичность — эвристика.** В chunk-split она выводится из
  `(session_id, camera, local_track_id)`, то есть доверяет локальному трекеру.
  Ошибки Edge-трекинга напрямую занижают метрику.

## 7. Воспроизведение

```powershell
cmake --build --preset local-release
ctest --preset local-release

# Aire / Auburn
powershell -ExecutionPolicy Bypass -File scripts/reid_eval_aire.ps1
powershell -ExecutionPolicy Bypass -File scripts/reid_eval_auburn.ps1

# вручную, с JSON-отчётом
.\build\local-release\Release\trafficmcmt_reid_eval.exe `
  --tracklets build\datasets\aire\cam-01.jsonl --json

# бенчмарк
.\build\local-release\Release\trafficmcmt_reid_bench.exe `
  --vectors 200000 --dim 512 --queries 200 --k 10 --index brute --json
```
